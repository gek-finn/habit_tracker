# habit_tracker

Учебное веб-приложение ежедневных привычек на Python, Flask и SQLite. Серверные HTML-шаблоны, локальные CSS/JavaScript, интерфейс на русском языке. Каждый пользователь имеет отдельные данные и IANA-часовой пояс.

## Выполненные этапы

Этап 1: регистрация, вход, выход через POST, личный доступ, Werkzeug-хеши, Flask-Login, CSRF, начальное ограничение входа и настройки development/production. Ручные проверки этапа 1 выполнены пользователем без проблем.

Этап 2: создание и редактирование ежедневных привычек; календарь месяца; установка и снятие отметок без перезагрузки с сохранением в SQLite. Название 1–80 символов после обрезки краёв, описание до 300, дата начала неизменяема после создания. Разрешённый диапазон дат: 01.01.2000–сегодня в часовом поясе пользователя. Для одной привычки и даты — одна отметка, повтор запроса идемпотентен. Порядок привычек: время создания, затем ID. Владение проверяется при каждом чтении и изменении.

Обновление базы: команда `flask --app wsgi:app upgrade-db`, повторяемое добавление таблиц в транзакции, без удаления существующих данных. Для новой базы — `init-db`. Авторизация и защита этапа 1 сохранены.

Этап 3: месячные выполнения и процент с округлением половин вверх; текущая и лучшая серии по исходной истории, без хранилища итогов. После изменения отметки показатели обновляются без перезагрузки. Доступный период включает сегодня, для архива ограничивается датой архивирования. Серии не ограничиваются выбранным месяцем.

Архивирование — POST с CSRF, владельцем и отдельным подтверждением. Первоначальная локальная дата сохраняется при повторных запросах. Основной режим содержит только активные привычки; архив — календарь и статистика только для чтения с навигацией по месяцам. Сервер запрещает редактирование архивных привычек и отметок. Таблицы и история не удаляются. `upgrade-db` повторяемо добавляет nullable-поле `archived_on`; новая база поддерживается через `init-db`, затем при необходимости `upgrade-db`.

Пользователь вручную проверил функции этапов 1 и 2 без проблем. Этапы 1–3 приняты пользователем. Этап 4 — финальная локальная проверка и подготовка инструкций размещения; новые продуктовые функции и цели не входят.

## Границы

В текущую работу не входят восстановление из архива, постоянное удаление, графики, уведомления, Telegram и другие интеграции, оплата, восстановление пароля, командные функции и публикация. После этапа 4 работа останавливается; следующий этап автоматически не начинается.

Будущая публикация: отдельный HTTPS-поддомен на Ubuntu 24.04 с Gunicorn, VPS 1 CPU / 1 ГБ RAM с другими приложениями. Инфраструктура не настраивается. Docker, Redis и Celery не добавляются.

Вопрос этапа 1 о чистой установке закрыт локально 15.11.2026: зависимости установлены из официального PyPI в отдельное окружение Windows с системным TLS-режимом pip 24.0. Проверка Linux остаётся обязательной до публичного запуска.

Другие проекты tracker и tracker_codex1, их базы, настройки и VPS не затрагиваются. Тесты — только на отдельных временных базах. Команды и ограничения: README.md; результаты: VERIFICATION.md.

## Подготовка размещения (этап 4)

Добавлены DEPLOYMENT.md и изолированные шаблоны habit_tracker для Ubuntu 24.04, одного worker Gunicorn на localhost, systemd, отдельного сайта Nginx, HTTPS, SQLite backup API и отката пары кода/базы. Предварительный домен habits.gilinsky.ru требует подтверждения. Описаны обязательное обследование ресурсов/портов и сохранение работающих Manager Tracker и робота ВК; достаточность VPS не заявляется.

Приложение поддерживает явное доверие одному прокси через TRUST_PROXY_HEADERS (по умолчанию выключено) и список TRUSTED_HOSTS. Отладка выключена, ключ обязателен в production, пробельный ключ запрещён, cookie безопасные. Схема базы на этапе 4 не менялась.

Первоначальная чистая установка не удалась; последующая диагностика и системный TLS-режим pip позволили установить зависимости в отдельное окружение Windows без подмены пакетов и без отключения TLS. Браузерные проверки этапа 4 недоступны из-за ограничений инструментов и остаются открытыми. Подробные фактические результаты — VERIFICATION.md. Публикация не начиналась; окончательная готовность обусловлена закрытием оставшихся проверок.

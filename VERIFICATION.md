# Этап 4: финальная локальная проверка и подготовка публикации

Дата: 15.11.2026. Продуктовые функции этапов 1–3 приняты пользователем. Этап 4 не добавляет новые функции или цели. Публикация не начиналась; окончательная готовность остаётся условной из-за непроверенной чистой установки и недоступной браузерной проверки.

## Чистая установка — пункт остаётся открытым

Создано отдельное `.venv-check-stage4`, Python 3.12.3, `include-system-site-packages = false`. Рабочее `.venv` не переустанавливалось, его зависимости не заменялись и не обновлялись.

Первая команда:

```powershell
python -m venv .venv-check-stage4
.\.venv-check-stage4\Scripts\python.exe -m pip install --no-cache-dir --index-url https://pypi.org/simple -r requirements-dev.txt
```

pip получил ReadTimeoutError при обращении к /simple/flask. Попытка остановлена и повторена через предусмотренный запрос разрешения на сеть:

```powershell
.\.venv-check-stage4\Scripts\python.exe -m pip install --no-cache-dir --index-url https://pypi.org/simple --retries 0 --timeout 20 -r requirements-dev.txt
```

Итог: `Could not find a version that satisfies the requirement Flask==3.1.3 (from versions: none)`, `No matching distribution found`. Дополнительный `pip index versions Flask` также не получил кандидатов. Точная причина недоступности кандидатов в этом сетевом окружении не установлена: по одному сообщению pip нельзя утверждать, что версии не существует. Официальная страница [Flask 3.1.3 на PyPI](https://pypi.org/project/Flask/3.1.3/) доступна через поисковый инструмент, что не подтверждает доступ pip.

В проверочном окружении остался только pip 24.0. Локальные исходники и системные библиотеки в него не подставлялись. Поэтому запуск приложения, создание базы и тесты **в чистом окружении не выполнены**. Пункт не закрыт. Ниже приведены отдельные проверки в прежнем окружении, а не доказательство чистой установки.

## Найденное и изменения

- В production ключ из одних пробелов ранее считался заданным. Теперь он отвергается с той же понятной ошибкой запуска, что и отсутствующий ключ; добавлен тест.
- Для размещения за одним Nginx добавлен явный `TRUST_PROXY_HEADERS=0/1` (по умолчанию 0), доверие только адресу и схеме ровно одного прокси. Это позволяет передать настоящий адрес в лимитер входа и схему HTTPS в проверку CSRF. Условия безопасности — loopback-bind и перезапись заголовков Nginx; не применять без этих условий.
- Добавлен необязательный `TRUSTED_HOSTS`; пример production ограничен предварительным habits.gilinsky.ru. Неверный Host отклоняется, проверено тестом.
- Подтверждены DEBUG=False, обязательный секрет и Secure/HttpOnly/SameSite=Lax через конфигурацию и тестовый HTTPS-контекст. Это **не проверка настоящего HTTPS**.
- Ошибок в проверенных серверных сценариях и обработчике отказа отметки не обнаружено. Архитектура и оформление не перерабатывались.

После этого управление браузером прекращено; ограничение не обходилось.

Настоящий телефон и экранный диктор также не проверялись.

Короткая ручная приёмка: открыть приложение; выполнить регистрацию, создание привычки, отметку/снятие и сверку статистики; клавишами Tab, Shift+Tab, Enter/пробел проверить фокус и раскрытие; на узком экране проверить прокрутку; в инструментах браузера воспроизвести отказ POST, убедиться в отсутствии ложного сообщения сохранения, восстановить связь и повторить; архивировать и проверить историю. При полном обрыве обеих операций — обновить календарь после восстановления связи.

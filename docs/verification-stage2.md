# Проверка этапа 2

## Реализовано

- Создание и редактирование своих ежедневных привычек, валидация названия/описания/даты. Дата начала после создания неизменяема, поддельное изменение отвергается.
- Календарь выбранного месяца с навигацией, ограничениями 01.2000–текущий месяц и стабильным порядком привычек. Текущий день выделен; даты до начала и в будущем недоступны. На узком экране первый столбец закреплён.
- Отметки без перезагрузки: явный JSON boolean, защита от повторного нажатия, идемпотентные операции, первичный ключ привычка–дата. При ошибке — сверка состояния через защищённый GET; при неуспешной сверке — неизвестное состояние и ссылка обновления.
- Проверка владельца на всех маршрутах привычек и отметок, существующие Flask-Login и CSRF сохранены.
- Безопасное обновление существующей SQLite-схемы: `upgrade-db`, явная транзакция, CREATE IF NOT EXISTS; без DROP TABLE или удаления базы. Новая база создаётся через `init-db` со всеми текущими таблицами.

## Браузер

В отдельной временной базе `.pytest_browser` на локальном порту 5001 выполнены:

1. Вход тестового аккаунта и пустое состояние календаря.
2. Создание привычки с описанием и датой по умолчанию.
3. Установка отметки без перезагрузки — показано «выполнено» и сообщение о сохранении.
4. Обновление страницы — отметка сохранилась.
5. Снятие отметки без перезагрузки — показано «не выполнено».
6. Переход в предыдущий месяц (без ещё не начавшейся привычки), затем вперёд к текущему. В текущем месяце дальнейший переход недоступен.
7. Ширина 390 px: визуально проверены вёрстка и горизонтальная прокрутка, название и описание остаются видимыми в закреплённом столбце. Параметры ширины браузера после проверки восстановлены.

Снимок: [мобильный календарь](docs/calendar-mobile.png). Проверочный сервер после завершения остановлен. Созданные для него файлы и тестовая база находятся только в игнорируемых каталогах внутри habit_tracker.

## Открытые проверки и ограничения

- **Чистая установка зависимостей из PyPI ещё не подтверждена.** Использовано подготовленное окружение этапа 1 с системными библиотеками и официальными исходниками недостающих пакетов внутри локального `.venv`. Зависимости на этапе 2 не добавлялись и не обновлялись. Подробности исходного ограничения — [отчёт этапа 1](docs/verification-stage1.md).
- Реальный телефон, клавиатурный цикл и программы чтения с экрана требуют ручной проверки. Программные подписи и aria-pressed присутствуют; это не полная проверка вспомогательных технологий.
- Потеря сетевого ответа/полный разрыв связи в браузере отдельно не воспроизводились. В клиенте предусмотрены повторное чтение состояния, сообщение и блокировка неизвестной ячейки.
- После наступления нового локального дня открытый календарь следует обновить. Сервер проверяет актуальную дату при каждом запросе.
- Вкладки не синхронизируются автоматически; последнее успешно сохранённое состояние определяет результат. Нет постраничной загрузки при большом количестве привычек.
- Сохранены ограничения этапа 1: лимит входа в памяти одного процесса, отсутствие восстановления пароля, ненастроенное доверие к прокси. Настоящие HTTPS-cookie и Gunicorn/Ubuntu не проверялись.

## Ручной сценарий

Обновить базу по README, запустить приложение, войти прежним аккаунтом. Создать привычку, поставить отметку, обновить страницу, снять отметку. Изменить название и описание, убедиться в неизменности даты начала. Переключить месяцы, проверить недоступные даты. На телефоне прокрутить календарь и проверить закреплённое название; клавиатурой — Tab, Enter/пробел. Во втором аккаунте привычки первого не должны отображаться.

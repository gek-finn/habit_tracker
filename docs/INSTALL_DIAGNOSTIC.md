# Диагностика чистой установки — 15.11.2026

## Итог

**Чистая локальная установка Windows подтверждена.** Все зафиксированные зависимости установлены обычным pip из официального PyPI/его хранилища files.pythonhosted.org в отдельное `.venv-check-stage4`. Локальные исходники, системные пакеты, сторонние зеркала и отключение TLS не использовались. Основное `.venv` и рабочая база не менялись.

Подтверждённый сбой — временный обрыв TLS-соединения при получении файла с files.pythonhosted.org. Конкретная низкоуровневая причина (сетевой фильтр, промежуточное оборудование, TLS-режим клиента и т. п.) **не установлена**. Успешная установка с truststore не доказывает, что причиной был сертификат: последующая контрольная загрузка без truststore тоже прошла. Нельзя утверждать ни неисправность PyPI, ни постоянную ошибку старого pip.

## Предыдущая попытка и повтор

Точная команда предыдущего этапа, зафиксированная в VERIFICATION.md:

```powershell
.\.venv-check-stage4\Scripts\python.exe -m pip install --no-cache-dir --index-url https://pypi.org/simple --retries 0 --timeout 20 -r requirements-dev.txt
```

Тогда: ReadTimeoutError при обращении к индексу, затем `Could not find a version that satisfies the requirement Flask==3.1.3 (from versions: none)` / `No matching distribution found`. Последние строки сами по себе не доказывали отсутствия версии.

В текущей диагностике команда с `--timeout 15` и затем её повтор с сетевым разрешением дошли до метаданных Flask на files.pythonhosted.org. Существенная часть ошибки (URL публичного пакета, без учётных данных):

```text
HTTPSConnectionPool(host='files.pythonhosted.org', port=443)
Max retries exceeded ... flask-3.1.3-py3-none-any.whl.metadata
SSLError(SSLEOFError(8, '[SSL: UNEXPECTED_EOF_WHILE_READING]
EOF occurred in violation of protocol (_ssl.c:1000)'))
```

Это обрыв TLS, а не сообщение CERTIFICATE_VERIFY_FAILED. Воспроизведение после штатного запроса разрешения исключает объяснение только первоначальным ограничением запуска команды, но не определяет конкретный сетевой компонент.

## Успешная установка

В том же отдельном окружении, без изменения системных настроек:

```powershell
.\.venv-check-stage4\Scripts\python.exe -m pip install --use-feature=truststore --no-cache-dir --index-url https://pypi.org/simple --retries 0 --timeout 15 -r requirements-dev.txt
```

Итог — Successfully installed для всех 17 зависимостей из фиксированных файлов. Truststore использует системное хранилище сертификатов с проверкой TLS; это поддерживаемая возможность pip 24.0, а не отключение проверки. С pip 24.2 системные сертификаты по умолчанию используются вместе с certifi: [официальная документация pip](https://pip.pypa.io/en/stable/topics/https-certificates/). В этом задании pip не обновлялся.

Контроль после установки, без truststore и без изменения установленных пакетов:

```powershell
.\.venv-check-stage4\Scripts\python.exe -m pip install --dry-run --ignore-installed --no-deps --no-cache-dir --index-url https://pypi.org/simple --retries 0 --timeout 10 Flask==3.1.3
```

Итог: метаданные и wheel скачаны, `Would install Flask-3.1.3`. Это дополнительно подтверждает восстановление обычного доступа; из-за этого связь успеха исключительно с truststore **не объявляется доказанной**. Глубокая причина первоначального TLS-обрыва остаётся неизвестной, но действующего блокера локальной установки на момент проверки нет.

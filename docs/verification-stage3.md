# Проверка этапа 3

## Реализовано

Месячные выполнения и процент, текущая и лучшая серии. Процент учитывает пересечение доступного периода и выбранного месяца, включает локальное сегодня и округляется половинами вверх. При отсутствии доступных дней — «Нет данных». Серии вычисляются по всей доступной истории исходных отметок; для архива текущая серия заменена на «В архиве».

Показатели размещены в раскрываемых блоках под календарём. Подписи различают выбранный месяц, сегодня и всю историю. POST отметки и последующий GET состояния возвращают один и тот же расчёт статистики. Клиент обновляет отметку и показатели вместе; запросы одной привычки сериализованы. При ошибке проводится сверка через GET; при неудаче неподтверждённые показатели скрываются и предлагается обновление.

Архивирование через страницу подтверждения с предупреждением, обязательным флажком, POST и CSRF. Записывается первая дата по часовому поясу владельца; повторный POST её не меняет. Активный список исключает архивные привычки; режим `view=archive` сохраняет навигацию по месяцам и показывает историю/статистику без возможности изменения, дату архивирования и пустое состояние. Сервер запрещает редактирование и POST отметок архивных привычек; чужие идентификаторы защищены проверкой владельца.

Авторизация и CSRF этапов 1–2 сохранены. Восстановление из архива, постоянное удаление, графики, уведомления, Telegram, оплата и командные функции не добавлялись.

## Обновление рабочей базы

До первого изменения создана копия через SQLite backup API: `instance/before-stage3-20261114-011931.sqlite3`. Копия находится внутри проекта, исключена из Git правилами instance/ и *.sqlite3.

Команда upgrade-db использует явную транзакцию BEGIN IMMEDIATE, проверяет столбцы habits через PRAGMA table_info и добавляет nullable archived_on только при его отсутствии. Пользователи, привычки и отметки не удаляются и не пересоздаются. Команда выполнена дважды, программно сравнены все существовавшие поля и записи трёх таблиц до/после — совпадают. PRAGMA integrity_check — ok. Выполнен и дополнительный запуск через обычный Flask CLI.

## Ручная приёмка

1. Обновить базу и запустить по README, войти прежним аккаунтом.
2. Раскрыть статистику, поставить/снять отметку сегодня и в прошлом; сверить пересчёт и повторить после обновления страницы.
3. Выбрать другой месяц: месячные значения меняются, серии остаются на сегодня/за всю историю.
4. Проверить отмену архивирования, затем подтвердить. Привычка исчезает из активных, но сохраняется с отметками и датой в архиве.
5. Проверить архив в другом месяце и на телефоне; с клавиатуры — переключатели, раскрытие статистики, флажок и кнопка.

- **Чистая установка зависимостей из PyPI ещё не подтверждена.** Использовано подготовленное окружение этапа 1; новых зависимостей на этапе 3 нет. См. [историю проверки этапа 1](docs/verification-stage1.md).

- Разрыв сети в браузере и одновременные изменения нескольких устройств отдельно не воспроизводились. Клиент сверяет ошибки, скрывает непроверенные показатели; сервер повторно проверяет архивный статус под блокировкой записи.
- Нет живой синхронизации вкладок и автоматической смены календаря/показателей в полночь: нужно обновить страницу. Сервер использует актуальное локальное сегодня.

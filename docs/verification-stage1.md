# Проверка этапа 1

Реализованы основа Flask + SQLite, публичная главная, регистрация с IANA-зоной, вход, POST-выход и закрытая страница «Мой трекер». Добавлены настройки development/production, CSRF, Flask-Login, scrypt-хеши Werkzeug, ограничение входа, безопасный next, WSGI-точка и GET /health. Зависимости зафиксированы, команды и ограничения описаны в README.

## Результаты

- Python 3.12.3, Windows: `python -m compileall -q habit_tracker tests wsgi.py` — успешно.
- `.\.venv\Scripts\python.exe -m pytest -q --basetemp .pytest_tmp` — **25 passed** (16,41 с). Каждый сценарий использовал отдельную временную базу. Рабочая база тестами не затрагивалась.
- `flask --app wsgi:app init-db` — успешно; создана пустая база в instance. Сохранение существующих данных при повторной инициализации дополнительно проверено тестом.
- Локальный сервер запущен на 127.0.0.1:5000, отладка выключена. В браузере открыты главная и регистрация, проверены русский текст, навигация и значение Europe/Kaliningrad по умолчанию; главная осмотрена визуально.
- После проверки локальный сервер остановлен.

## Особенности окружения

Обычная установка из PyPI не прошла: TLS-соединение обрывается (UNEXPECTED_EOF). Это повторилось и при запуске с дополнительным разрешением на сеть. Проверить чистую установку `pip install -r requirements-dev.txt` в этом окружении не удалось.

Для фактического запуска тестов локальное `.venv` создано с доступом к уже установленным системным библиотекам (глобальные пакеты не изменялись). Три отсутствовавшие библиотеки загружены из официальных GitHub-тегов и их исходные пакеты помещены только в `.venv/Lib/site-packages`: Flask-Login 0.6.3, Flask-WTF v1.2.2, WTForms 3.2.1. Архивы находятся в игнорируемой `.dependencies`. Это обход недоступности каталога пакетов для проверки, а не рекомендуемый способ установки. Все используемые версии отражены в requirements-файлах. Обычные команды установки для нового окружения приведены в README.

## Что проверить вручную

На реальном телефоне: вёрстку, поиск IANA-зон и клавиатурную навигацию. В браузере: полный цикл регистрации, входа и выхода, ошибки и очистку полей пароля, второй аккаунт в приватном окне. Автоматические проверки этих серверных сценариев прошли; реальная мобильная визуальная проверка не выполнялась.

На будущем этапе публикации: HTTPS-cookie, Gunicorn/Ubuntu, права на SQLite, резервные копии и явную настройку доверенного прокси. Серверные команды не выполнялись.

## Ограничения

Лимит 5 попыток входа за 60 секунд хранится в памяти одного процесса, сбрасывается при перезапуске и не объединяется между процессами; за ненастроенным прокси все посетители могут разделять один IP. Регистрация не имеет отдельного лимита. /health не проверяет доступность базы. Миграции, восстановление пароля и остальные этапы не реализованы.

Другие проекты E:\vibecoding\tracker и E:\vibecoding\tracker_codex1, их код, базы и настройки не изменялись. Подключений к VPS не было. Работа ограничена этапом 1, следующий этап не начат.
